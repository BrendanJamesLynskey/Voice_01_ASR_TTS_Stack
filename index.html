01

The Voice Stack — ASR → LLM → TTS

A voice assistant has three serial latency contributors. The user speaks; the ASR layer produces text; the LLM generates a reply; the TTS layer speaks it. Each hop adds latency, and the gaps compound: a 300 ms ASR result + 400 ms TTFT + 200 ms TTS first-chunk = 900 ms to first audio byte — already over the 800 ms human-comfort threshold.

Key latency terms

ASR final latency

Time from end-of-utterance to full transcript. Streaming services return partials (100–150 ms update cadence) but the stable final may take 300–600 ms on server-side models like Whisper Large-v3.

LLM TTFT

Time To First Token. GPT-4o at median ≈ 320 ms; Claude 3 Haiku ≈ 280 ms; Llama 3.1-8B on A10G self-hosted ≈ 180 ms. Prefill cost dominates for short prompts.

TTS first-chunk

Time from text-in to first PCM audio out. ElevenLabs Flash v2.5: ≈ 75 ms; Cartesia Sonic: ≈ 90 ms; OpenAI TTS-1: ≈ 200 ms. All measured at p50 from US-East.

The 800 ms budget

Human conversation research (Stivers et al., PNAS 2009) puts the comfortable gap between speakers at 200–400 ms. A voice bot perceived as “fast” needs total pipeline latency under 800 ms; under 500 ms feels near-human. Every architectural decision in this series is ultimately about defending that budget.

02

Whisper — Architecture, Multilingual, Fine-Tuning

OpenAI’s Whisper (open-sourced September 2022, current checkpoint whisper-large-v3-turbo released October 2024) is a Transformer encoder–decoder trained on 680,000 hours of weakly supervised multilingual audio. It is the reference model against which every cloud ASR service is benchmarked.

Architecture at a glance

Encoder — log-Mel CNN + Transformer

  • Input: 80-channel log-Mel spectrogram, 30-second window at 16 kHz
  • Two 1-D conv layers (kernel 3, stride 1 & 2) → GELU → 1500-frame sequence
  • Sinusoidal positional embeddings → N Transformer encoder blocks
  • Large-v3: 32 encoder layers, dmodel = 1280, 20 heads

Decoder — causal Transformer with cross-attention

  • Auto-regressive over a 50,257-token BPE vocabulary (GPT-2 tokeniser)
  • Special tokens encode task: <|transcribe|>, <|translate|>, language ID e.g. <|en|>, <|fr|>
  • Timestamp tokens at 20 ms resolution for word-level alignment
  • Large-v3: 32 decoder layers — 1.55B total parameters

Fine-tuning workflow

python — Hugging Face fine-tune with Seq2SeqTrainer
from transformers import WhisperForConditionalGeneration, WhisperProcessor
from transformers import Seq2SeqTrainer, Seq2SeqTrainingArguments

model     = WhisperForConditionalGeneration.from_pretrained("openai/whisper-small")
processor = WhisperProcessor.from_pretrained("openai/whisper-small")

# Force the decoder to transcribe (not translate) English
model.generation_config.forced_decoder_ids = processor.get_decoder_prompt_ids(
    language="english", task="transcribe"
)

args = Seq2SeqTrainingArguments(
    output_dir="whisper-finetuned",
    per_device_train_batch_size=16,
    gradient_accumulation_steps=1,
    learning_rate=1e-5,
    warmup_steps=500,
    max_steps=4000,
    fp16=True,
    predict_with_generate=True,
    generation_max_length=225,
    metric_for_best_model="wer",
)
Hallucination & repetition

Whisper is notorious for hallucinating plausible-sounding phrases on near-silence or background noise. In production, gate ASR calls with a VAD (e.g. Silero VAD) and reject any segment whose audio energy falls below –40 dBFS RMS. The no_speech_prob field in Whisper’s output gives a secondary check: threshold at 0.6 is a common heuristic.

Deepgram WebSocket wire format

python — Deepgram Nova-3 streaming over WebSocket
import asyncio, websockets, json

URL = ("wss://api.deepgram.com/v1/listen"
       "?model=nova-3&encoding=linear16&sample_rate=16000"
       "&channels=1&interim_results=true&endpointing=300")

async def stream_asr(audio_queue: asyncio.Queue) -> None:
    headers = {"Authorization": f"Token {DG_API_KEY}"}
    async with websockets.connect(URL, extra_headers=headers) as ws:
        async def sender():
            while (chunk := await audio_queue.get()) is not None:
                await ws.send(chunk)            # raw PCM bytes
            await ws.send(json.dumps({"type": "CloseStream"}))

        async def receiver():
            async for msg in ws:
                data = json.loads(msg)
                alt = data["channel"]["alternatives"][0]
                if data["is_final"]:
                    on_final_transcript(alt["transcript"],
                                          alt["words"])

        await asyncio.gather(sender(), receiver())
Interim vs. final results

interim_results=true fires a transcript event every ~150 ms with the partial hypothesis. Setting endpointing=300 tells Deepgram to emit a final result after 300 ms of trailing silence, with speech_final: true. This flag — not is_final — is the reliable end-of-utterance signal in the Deepgram API. Confusing the two is the most common integration bug.

TTS Landscape — ElevenLabs, Cartesia, OpenAI, PlayHT, Coqui

Text-to-speech has bifurcated into two tiers: quality-first models that prioritise naturalness and expressiveness (ElevenLabs, PlayHT) and latency-first models that sacrifice some naturalness for sub-100 ms first-chunk times (Cartesia Sonic, ElevenLabs Flash). Choosing a voice

Pre-built voice libraries

ElevenLabs ships 3,000+ voices across language and accent; Cartesia has ~200 curated voices plus a growing community library. Both APIs accept a voice_id string and a model_id string independently — swap the model without re-choosing the voice.

Clone vs. design

For a branded assistant you either clone an existing human voice (5–30 s sample needed; see slide 06) or use a voice-design API (ElevenLabs /v1/voice-generation, PlayHT) that lets you prompt-engineer an accent, age, and timbre without any speaker recording.

Audio encoding tip

Request pcm_16000 (raw 16-bit signed PCM at 16 kHz) from both ElevenLabs and Cartesia — it avoids an MP3 decode step on the client. The raw format adds ~10 % bandwidth but reduces end-to-end playout latency by 30–60 ms because there is no codec buffer to fill before the first decoded frame is ready.

05

Latency-First TTS — Cartesia Sonic, ElevenLabs Flash

Both Cartesia Sonic 2 and ElevenLabs Flash v2.5 are purpose-built for real-time conversational use. They share two architectural bets: state-space models (SSM) instead of attention-heavy Transformers for the acoustic decoder, and streaming chunked inference that emits audio before the full sentence is processed.

Cartesia Sonic 2 — technical internals

Mamba SSM backbone

Cartesia’s model uses a Mamba-family state-space layer (selective scan, hardware-optimised CUDA kernel) for the acoustic decoder. SSMs have O(L) rather than O(L²) memory in the sequence dimension, which matters for multi-sentence utterances. The state is a fixed-size vector rather than a KV-cache, enabling incremental autoregressive decoding without cache growth.

Streaming API — WebSocket protocol

The client sends a single JSON message with model_id, voice, and transcript. Cartesia starts returning audio chunks (base64 PCM or raw bytes depending on output_format) within ~90 ms of the first request byte. Chunk size is ~4096 samples ≈ 256 ms at 16 kHz — keep playout buffer ≥ 3 chunks to absorb jitter.

python — Cartesia Sonic streaming (cartesia-python 1.x SDK)
from cartesia import Cartesia
import pyaudio

client = Cartesia(api_key=CARTESIA_API_KEY)
pa     = pyaudio.PyAudio()
stream = pa.open(format=pyaudio.paInt16, channels=1,
                   rate=44100, output=True)

for output in client.tts.bytes(
    model_id="sonic-2",
    transcript="Hello, how can I help you today?",
    voice={"mode": "id", "id": "a0e99841-438c-4a64-b679-ae501e7d6091"},
    output_format={"container": "raw", "encoding": "pcm_s16le",
                   "sample_rate": 44100},
    stream=True,
):
    stream.write(output)

stream.stop_stream()
stream.close()

ElevenLabs Flash v2.5 — design choices

Input streaming

Flash v2.5 exposes a WebSocket input-streaming endpoint (wss://api.elevenlabs.io/v1/text-to-speech/{voice_id}/stream-input?model_id=eleven_flash_v2_5). You push sentence fragments as they arrive from the LLM token stream — Flash starts synthesising before the sentence is complete, overlapping LLM and TTS latency. ElevenLabs calls this “text-to-speech streaming with auto-flush”.

Alignment data

Set enable_ssml_parsing=false and output_format=pcm_16000 for minimum overhead. The response stream carries optional alignment chunks with word-level timestamps; these are useful for driving lip-sync or caption overlays but add ~5 ms per chunk, so disable them if not needed.

Sentence-boundary injection

For both Cartesia and Flash, send a full sentence — not a raw stream of tokens — as a single WebSocket message. Splitting a sentence across multiple sends forces the model to re-attend to an incomplete phonetic context and degrades prosody. A practical pattern: buffer LLM tokens until a sentence-final punctuation mark or after a 200 ms silence in the token stream, then flush.

06

Voice Cloning — Capabilities & Ethics

Modern voice cloning can produce a highly convincing replica of a speaker’s voice from as little as 5 seconds of reference audio (ElevenLabs Instant Voice Clone) or produce near-broadcast quality from 30+ seconds. The capability is commercially useful for product personalisation and accessibility — and simultaneously one of the most directly misuse-prone generative AI features in production.

Technical approaches

Speaker embedding (fast)

Extract a d-vector or x-vector from the reference via a pretrained speaker-encoder (e.g. GE2E, ECAPA-TDNN). Condition TTS decoder on the embedding. Works from 3–30 s. Quality limited by encoder generalisation. Used in ElevenLabs Instant Clone and Cartesia Voice Changer.

Fine-tune adaptation (better)

LoRA-adapt the full TTS model on 1–10 minutes of reference audio. Captures prosody rhythms, breath patterns, and filler-word habits. ElevenLabs “Professional Voice Clone” tier; Coqui XTTS-v2 supports this via tts.tts_to_file(speaker_wav=...). Requires compute; not realtime at clone time.

Zero-shot diffusion (cutting edge)

Models such as Voicebox (Meta, 2023) and E2 TTS / F5-TTS (2024) use flow-matching or diffusion over a mel-spectrogram conditioned on in-context reference audio. No speaker-encoder training required. F5-TTS achieves near-parity with full fine-tune from a 5-second clip.

Quality vs Latency vs Cost Trade-Offs

There is no free lunch. Every dial in the voice stack couples to at least two others. This slide maps the primary trade-offs so you can make an explicit decision rather than stumbling into a bad default.

Decision framework

Interactive voice bot

Latency dominates. Use Cartesia Sonic 2 or ElevenLabs Flash. Accept MOS ~4.2 over MOS ~4.4. Total pipeline must stay under 800 ms; every 50 ms TTS first-chunk saving is directly perceptible.

Async narration / IVR prompt

Quality dominates; latency is irrelevant. Use ElevenLabs Multilingual v2 or PlayHT PlayDialog. Render overnight. Perceptible prosody gains justify the 4× price premium vs. TTS-1.

High-volume call centre

Cost dominates. OpenAI TTS-1 at $0.015/Kc or self-hosted Coqui XTTS-v2. At 1M characters/day the difference between TTS-1 ($15/day) and ElevenLabs Flash ($110/day) is $35K/year. Fine-tune XTTS-v2 on a branded voice to recoup quality.

Measure, don’t guess

Run your own MOS evaluation with the DNSMOS model (Microsoft, 2021) or ViSQOL (Google) on a representative sample of generated audio before committing to a provider. Published MOS figures are measured on clean read-speech; your domain may have names, acronyms, and brand jargon that degrades quality unevenly across providers.

F5-TTS — zero-shot flow matching

Model architecture

F5-TTS (Yushen Chen et al., 2024; SWivid/F5-TTS on HuggingFace) uses a flow-matching diffusion head over a duration-predicted mel-spectrogram. The reference speech segment is encoded into a conditioning vector via a DiT (Diffusion Transformer) block. Inference: ~30 NFE (function evaluations) at a 24 kHz sample rate, typically 400–600 ms on an A10G.

Usage — 5-second clone

Provide a ref_audio_path (5–30 s WAV), a ref_text transcription of that clip, and the gen_text to synthesise. F5-TTS matches timbre and prosody without any fine-tuning. The speaker embedding is computed on-the-fly each call — useful for customer-service bots where each caller gets their own voice reflected back during confirmation steps.

GPU requirements — minimum viable self-hosted stack

faster-whisper large-v3-turbo: 4 GB VRAM at float16 — fits an RTX 3060 or A10G. Coqui XTTS-v2: 3.5 GB VRAM; F5-TTS: 6 GB VRAM. A concurrent ASR+TTS pipeline needs at least an A10G (24 GB). Batch requests where possible; a single A10G can handle ~20 concurrent ASR or ~8 concurrent TTS streams before queuing latency degrades the user experience.

09

What to Take Away

  • The pipeline has three latency contributors. ASR final latency + LLM TTFT + TTS first-chunk. The 800 ms comfort budget demands each stay under ~250–300 ms. VAD-gated streaming ASR and Flash/Sonic TTS are the fastest levers.
  • Whisper is the reference ASR model but not a real-time service. Use faster-whisper with the large-v3-turbo checkpoint and CTranslate2 float16 for self-hosted; use Deepgram Nova-3 or Soniox for cloud streaming at <200 ms latency.
  • TTS has bifurcated. For interactive voice: Cartesia Sonic 2 (~90 ms first chunk, $0.065/Kc) or ElevenLabs Flash v2.5 (~75 ms, $0.11/Kc). For narration quality: ElevenLabs Multilingual v2 or PlayHT PlayDialog.
  • Voice cloning requires explicit consent. The legal landscape (EU AI Act, California SB 1047) mandates it. Always apply a steganographic watermark (AudioSeal or C2PA) to synthetic audio in production.
  • Open-source is viable. faster-whisper + Coqui XTTS-v2 / F5-TTS on a single A10G (24 GB) covers small-scale deployment. F5-TTS zero-shot cloning from 5 s of reference audio is near commercial quality.
